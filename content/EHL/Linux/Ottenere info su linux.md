L'enumerazione è una fase fondamentale di qualsiasi [[Penetration Test|penetration test]]. ==L'obiettivo principale è costruire una comprensione completa dell'ambiente di destinazione, analizzando il sistema operativo, gli account utente, i servizi in esecuzione, la rete e la struttura del file system==. Questo processo non deve essere visto come una lista di controllo rigida, ma come un'attività iterativa in cui ogni nuova informazione guida le indagini successive, influenzando direttamente il successo delle future attività di "exploitation" ed "escalation" dei privilegi.

## Comandi più utilizzati

Di seguito si può stilare un elenco con tutti i vari comandi inerenti ai sistemi operativi linux:

- **Identificazione del Sistema e del Kernel:** Per scoprire la distribuzione Linux e la sua versione, si consiglia di consultare i file all'interno della directory `/etc/` (come `/etc/issue`, `/etc/lsb-release` o `/etc/redhat-release`). Identificare la versione del kernel e la sua architettura (32 o 64 bit) è vitale per scovare potenziali vulnerabilità. Questo avviene tramite comandi come `uname -a`, analizzando i messaggi di boot con `dmesg | grep Linux` o controllando il file `/proc/version`.
- **Ambiente Utente e Processi in Esecuzione:** L'analisi delle variabili d'ambiente e dei file di configurazione della shell (come `/etc/profile`, `~/.bashrc` e l'uso dei comandi `env` o `set`) aiuta a comprendere il contesto dell'utente e a individuare script personalizzati, credenziali nascoste o impostazioni errate che possono essere sfruttate. Parallelamente, è necessario mappare i processi attivi per determinare la superficie di attacco, prestando molta attenzione ai servizi che girano con privilegi elevati (come l'utente _root_), monitorabili con comandi come `ps aux`, `ps -ef` o `top`.
- **Applicazioni, Configurazioni e Credenziali in Chiaro:** Enumerare i software installati tramite gestori di pacchetti (`dpkg -l`, `rpm -qa`) o ispezionando i binari (`/usr/bin/`) aiuta a scovare programmi obsoleti e vulnerabili. Inoltre, la revisione accurata dei file di configurazione (es. `/etc/syslog.conf`, `/etc/apache2/apache2.conf`, `/etc/my.conf`) permette di identificare impostazioni errate. Un passaggio critico è la ricerca all'interno di file o script di nomi utente e password salvati in chiaro (plaintext), operazione che può essere eseguita tramite tecniche di pattern matching con il comando `grep` (es. `grep -i pass <file>`).
- **Rete, Connessioni e Servizi Web:** Comprendere le impostazioni di rete (tramite file come `/etc/resolv.conf` o comandi come `iptables -L` e `hostname`) è essenziale per mappare l'infrastruttura, scoprire le regole del firewall e individuare opportunità di "pivoting". Si analizzano anche le connessioni di rete attive, le porte in ascolto e gli utenti loggati al sistema (usando `netstat`, `lsof -i`, `w` o `last`) per capire chi comunica con la macchina. In ambito web, la scansione di directory come `/var/www/html/` può rivelare file nascosti, backup o codice sorgente sensibile.
- **Privilegi, Chiavi SSH e File System:** È fondamentale identificare le autorizzazioni dell'utente corrente (con `id`), la lista degli utenti di sistema (leggendo `/etc/passwd`) e le configurazioni di _sudo_ (`/etc/sudoers` o `sudo -l`). Le chiavi SSH (pubbliche e private, situate in `~/.ssh/`) rappresentano un obiettivo primario, poiché se mal protette garantiscono accesso diretto e movimenti laterali nella rete.
- **Gestione della Shell e Scrittura File:** Se, a seguito di un accesso iniziale, ci si trova in un ambiente limitato (una "prigione"), bisogna forzare o generare una shell interattiva (es. tramite script Python) per poter eseguire comandi complessi. Infine, l'indagine deve estendersi ai file system montati (usando `mount`, `df -h` o leggendo `/etc/fstab`) e all'individuazione metodica di directory in cui l'utente possiede permessi di scrittura o esecuzione (attraverso l'uso mirato del comando `find`). Scrivere ed eseguire file in queste posizioni è cruciale per eseguire payload, mantenere l'accesso al sistema o innalzare i propri privilegi.
